## 1. 现状（已核对，不要重新猜）

`lib/client.js` 是**经典脚本**，整份被 `window.__ModuleLoader__.load({ id: 'dsh-zcode-native', factory: require => {…} })` 包住，`exports.inject = ['slots', 'sidebarRightTabs']`。`apply(ctx)` 里现在做两件事：

1. `ctx.sidebarRightTabs.register({ id: 'zcode-native', kind: 'zcode-native', priority: 'extension', … })`，再 `ctx.slots.inject('sidebar.right.pane.tab' | 'sidebar.right.pane.tab.title', …)` —— 右侧栏的「ZCode」页签 + 面板主体。**这部分不动。**

## 2. 任务 A：把卡片从「设置」搬到「插件 → 已安装 → dsh-zcode-native」

DSH 0.14.0 的插件管理器页就是组合包详情页（左侧「插件」→「已安装」→ 点 `dsh-zcode-native`）。它自带三个配置 slot（契约取自宿主 `app.asar` 内文档原文）：

| slot | 键 | 位置 |
| --- | --- | --- |
| `plugins.bundle.config` | **组合包的包名** | 组合包页面「描述」与「行」之间 |
| `plugins.row.config` | `<包名>#<行 id>` | 某一行自己的页面（要求 patch 里声明该行，本项目没有行，**不要用**） |
| `plugins.item` | Host 条目 id | 官方插件配置分组（不适用） |

所以用 `plugins.bundle.config`，`key` 用包名 `dsh-zcode-native`（不是 `id`，也不是 locale 命名空间）。

宿主里同类插件的真实写法（`profiles/desktop/node_modules/dshmarket/client/client.js:19073`）：

```js
ctx.slots.inject('plugins.bundle.config', () => ctx.slots.register({
  name: 'plugins.bundle.config',
  key: 'dshmarket',                 // 它自己的包名
  locale: NS,                        // 可选；本项目没有 locale 服务，不要传
  inject: () => ({ t }),             // 可选；本项目不要传
}, (ownerProps = {}) => ownerProps.view === 'summary'
  ? null                             // 组合包页不渲染摘要视图
  : h(SettingsCard, { … })))        // view === 'page' 时画整张卡片
```

改造要求：

1. 删除 `settings.section` 的注册（`apply()` 里那一行）。设置面板里从此不再出现「ZCode Native」。
2. 新增 `plugins.bundle.config` 注册，`key: 'dsh-zcode-native'`，只处理 `view === 'page'`；`view === 'summary'` 以及任何未知 view 一律返回 `null`（宿主会拿 summary 视图问一次，返回元素会画到错的位置）。
3. 页面里同时给出两样东西，顺序固定：**先是页签开关**（复用现有 `ZcodeNativeSection` 的语义：写 `localStorage['dsh-zcode-native:sidebar']` = `on`/`off`，并 `dispatchEvent(new Event('storage'))`？不需要——现有实现靠 `window` 的 `storage` 事件监听，同页 `setItem` 不触发，所以开关自己可以直接调用既有的 `syncSidebar` 路径，读现在的代码照做，别发明第二套状态）。
4. **然后是状态面板**（任务 B 重画的 `PanelBody`）。
5. 页签开关关掉时，侧栏三件套仍然注销、面板仍可显示「已关闭，可在下方开启」——现有 `pref=off` 语义必须原样保留（测试会卡它）。
6. **不要**给 `settings.plugins.tab` 注册新标签页，**不要**动 `cordis.patch.yml`（本插件是单行 bundle，没有行，也不需要声明行）。

如果宿主里该 slot 不出现（旧版 DSH），`ctx.slots.inject` 本来就不会回调，属于可接受降级：功能退化为「没有设置入口」，侧栏不受影响。不要为此写 try/catch 或 feature flag。

## 3. 任务 B：美化侧栏那张卡片

参考 **Modern Web Guidance**（Google Chrome 团队维护的 web 最佳实践 skill 包，<https://github.com/GoogleChrome/modern-web-guidance>），按它的口径重画，别用「AI 默认观感」。

先取指引，再动手（这三条命令可以真跑）：

```bash
npx modern-web-guidance@latest search "compact status card layout hierarchy"
npx modern-web-guidance@latest retrieve "<上一条返回的 guide id>"
npx modern-web-guidance@latest search "dark mode color tokens contrast"
```

硬约束（宿主环境决定，违反就白做）：

- 只能用 `require('react')`。宿主只注入 react，没有别的第三方库，**不允许新增依赖**。
- 经典脚本，不能出现 `import` / `export` 语句（现有测试会失败）。
- 样式要么内联对象，要么在 `apply()` 里插一次 `<style>` 元素（`document.head.appendChild`）。**禁止** `@import`、外部字体、`backdrop-filter` 毛玻璃、`box-shadow` 堆叠。
- 颜色必须走宿主 token（下面这些在宿主里已存在），不要再硬编码 `#c0392b`：
  `--dsh-content-font-size`、`--dsh-content-font-size-secondary`、`--dsh-content-font-delta`、`--dsh-sidebar-row-padding`、`--dsh-sidebar-label-gap`、`--dsh-sidebar-paint-inset`、`--dsh-scrollbar-thumb`、`--dsh-button-outline-color`、`--dsh-code-font-size`。
  字号只用这两个变量：`font-size: var(--dsh-content-font-size-secondary)`，说明性文字再乘 `--dsh-content-font-delta`。
- 默认主题（浅色）和暗色都要能看：不要写死 `#fff` 背景与 `#333` 文字；需要底色时用 `color-mix(in oklab, currentColor 6%, transparent)` 这类与前景绑定的表达式。
- 可访问性：开关是真 `<button>`，带 `aria-pressed`；状态色不能单独承载语义（错误除了红色还要有文字「错误」）；切换时不丢焦点。
- 动效只允许 120–200ms 的透明度/位移过渡，且服从 `prefers-reduced-motion`。

内容结构（要信息层级，不要五行等宽 label）：

1. 顶部一行：`ZCode` 标题 + 连接状态点（已连上 / 未运行 / 错误）+ 刷新按钮（现有 `renderBoard` 的刷新逻辑保留）。
2. 主体：账号与套餐放一起（套餐名 + 倒计时），余额单独一行（`available === false` 时写「余额不可用（原因）」并给次级色，**不要显示 0**）。
3. 底部：客户端版本与页面标题作为次级信息，字号最小、`opacity` 不低于 0.55。
4. 空态：`fetch` 还没回来时给一行「读取中…」，不要闪空白；错误时保留上一次成功的数据并标注「数据来自 hh:mm:ss」。
